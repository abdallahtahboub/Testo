# Autestiq 0.5.0 — the first release (Milestone 5.1, pilot readiness)

> **Release notes.** The first release to `main`: everything on `develop` up to the release commit. Not deployed
> anywhere yet: hosting and an email provider are the owner's decisions (`docs/open-questions.md`).
> **Commit:** the merge of `release/0.5.0` into `main`, tagged `v0.5.0` by the owner.
> **Worker image:** built from that commit (`src/Autestiq.Worker/Dockerfile`); its digest is written here when it is
> first built for a host. Images are not built reproducibly, so the digest is per build.

## What is in it

**The first customer flow (Milestone 5, ADR-0030):** projects and test environments with proofs of ownership,
production off by default; a test described in a sentence, the site explored and the AI's plan written only with the
project's AI permission; approval with an explicit tick for steps that may change data; runs in a sealed container
per run; results with evidence; the approved test downloaded as Python.

**Pilot readiness (Milestone 5.1):**
- planning attempts recorded before each AI call, a lease that recovers interrupted planning, one planning step per
  deployment (ADR-0037);
- operator `migrate` and `migrations`, `/health/live` and `/health/ready` (ADR-0039);
- email through any SMTP relay, and `create-organization` for an instance's first owner (ADR-0040);
- readiness refuses a key ring that does not match the database; `key-ring-reset` for one lost for good (R-20);
- no download of a plan whose pass would rest on the test account's own value (ADR-0033);
- a site that cannot be reached is reported as such, never as a failure of the application (ADR-0026 amendment);
- content-free analytics views and the operator's `rehearsal-report`;
- a pilot runbook, rehearsed locally (`docs/operations/`).
- a test or run page that refreshes itself no longer ends its session when a person saves or clicks at the same
  moment: each page makes one data call at a time (`DataTurns`), found by CI on this release's own pull request.

## What was measured

The AI planner on the release candidate `v0.5.0-rc.1` (ADR-0020): no false positive in any run; the unseen sets as
before with acting exploration (demo shop 20 of 20, invoice desk 24 of 24); read-only exploration remains the weak
point (demo shop 4 of 20, clinic 8 of 22); every tester-stated result confirmed or caught. Five runs and PetClinic did
not complete for lack of API credit and are not counted.

## Known limits

- Not deployed; no host, no email provider chosen; TLS, alerting and log collection wait for hosting.
- Read-only exploration, a customer site's default, is markedly weaker than acting exploration.
- Before real customer data: the minimized AI mode (G-2), lifecycle and deletion of snapshots and planning payloads
  (G-5), least-privilege database roles (R-19), the composite environment key (R-18).
- Six of the seven testing-journey modules are shells.
